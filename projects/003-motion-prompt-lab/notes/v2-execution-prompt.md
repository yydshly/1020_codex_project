# V2 完整执行提示词：让一枚收藏标记成为研究档案

这是为当前真实项目独立编写的完整制作指令，可复制后执行。它不是原帖全文、译文或逐句改写，也不是一次未经干预的单轮模型调用记录。原帖入口与对应关系见 `original-prompt-guide.md`；实际执行、修订和未通过项另见制作与评审记录。

## 任务及成功条件

你负责导演、设计、动画、声音、代码与最终交付。为真实的「GitHub 项目研究集」制作第二版 20 秒产品介绍片。已有第一版需要保留，让观众在同一网页中比较两版的动作、信息表达和结果。

这次创作目标是让观众看见：一个被收藏的项目，可以进入有来源、有原理解释、有待执行实验的研究档案。看完后应能说出产品名称、用途，并找到真实仓库入口。

不能把“生成了 MP4”当作完成。主体必须在镜头之间保持可追踪的身份，转场要发生在内容和几何上。请做到连续轮廓变形、主次动作的时间层次、可辨认的预备与回落、随动作产生的空间变化，以及稳定可读的最终信息。把这些要求全部保留到验收表中；若没做到，修正并重新渲染，不得删掉要求来获得通过。

## 固定任务信息

- 受众：经常收藏开源工具，希望理解原理并继续实践的开发者。
- 场景：产品介绍；20 秒；1280×720；16:9；60 fps；共 1,200 帧；H.264 / yuv420p + AAC。
- 与 V1 使用同一主题、时长、尺寸与帧率。V1 文件不改写。
- 唯一最终行动入口：`github.com/yydshly/1020_codex_project`。
- 本项目工作目录：`projects/003-motion-prompt-lab`。素材依据来自当前本地工作树，不把尚未发布的文件描述成线上已可使用。
- 001 项目为 cyber-xiaowan 的研究；002 为六个 AI 内容工具的原理与实践。002 中选 Kokoro 展示“文稿进入语音模型、输出语音”的原理。
- Kokoro 动画只是原理示意。没有真的运行模型时，不能用声音波形、完成提示、耗时或结果页面制造“本机验证成功”的印象。
- `README.md`、`notes/sources.json`、`notes/07-experiments.md` 确实存在，但实验计划存在不等于实验已经通过。
- 没有官方图形标识时使用产品名称字标。不要捏造官方 logo、用户评价、性能数据、价格、排名或验证结果。

## 开始前的证据准备

读取仓库 README、001/002 项目元数据、002 的研究说明、来源记录与实验计划。整理出每个实际名称、状态、文件名和技术描述的来源路径、文件哈希、短依据与出现时间。

把原创广告文案单独标记。比如“收藏之后，理解开始”是表达意图，不是可测量的产品承诺。事实与创作修辞不能混在同一证据栏。

至少实际观看两段合适的官方动效参考，抽帧说明某一秒发生了什么、哪些边缘或对象延续到下一秒、主体与附属元素怎样错开动作。明确观看的是整片还是短片段，不凭工作室名气推测内容。第三方素材只供内部研究，不加入成片或公开下载。

## 方向选择与叙事

先比较三个方向：收藏标记长成档案、研究手册翻页、问题穿过知识网络。选择第一个：它能把产品含义与轮廓变形统一，也便于观众确认前后是同一个物体。

全片有三个应当让人记住的动作：

1. 星形收藏标记通过同一组轮廓点收拢成 002 编号牌，再伸展成研究档案卡片。
2. 卡片展开成目录，目录里被点击的 Kokoro 条目从自己的位置长成工作台。工作台再收束成原理图的中心模块，输入与输出有因果次序。
3. 原理图收回 README.md；来源与实验计划从研究说明背后展开。最后这些文件收拢为刚才的 002 档案，移到最终产品名旁边。

不要把语音波形直接变成来源文件，这会误导观众以为模型输出就是研究证据。让波形作为插图回到 README，然后揭示来源与实验层。

## 分镜、构图与可读性

按以下八个时间段组织。重要构图的更新间隔保持在约 1.4–3.5 秒；不要为了凑数字硬插不相关镜头。

| 时间 | 观众要理解的内容 | 连续交接的对象 |
| --- | --- | --- |
| 0–2.5s | 收藏只是研究的起点；开场第一帧就有完整标题与主体 | 星形→002 牌→卡片 |
| 2.5–5s | 研究集确实有目录与项目 | 卡片外框→目录窗口 |
| 5–7.5s | 从具体条目进入工具原理 | Kokoro 行背景→工作台→模型模块 |
| 7.5–10s | 文稿通过语音模型变成语音的示意 | 输入线条、模块和输出曲线 |
| 10–12.5s | 原理解释只是研究说明的一部分 | 模块边界→README；曲线回到页内 |
| 12.5–15s | 说明有来源，实验仍待执行 | 同一页后方展开来源与实验文件 |
| 15–17s | 这些内容属于同一份 002 档案 | 文件层合拢→档案 |
| 17–20s | 产品名称、价值与真实入口 | 档案归位，名称和网址稳定可读 |

先完成分镜评审，再做三个代表帧：开场档案、语音原理图、来源与实验展开。审查构图、字号、层级、文字长度、对象占比和前后身份。

关键标题至少留出 0.7 秒稳定阅读，按内容量增加时间；目标是一眼能读的短句，避免长句跟着剧烈运动。片尾完整网址从 17 秒至结束保持清晰。画面外缘留约 5% 安全空间；场景内页允许层叠，但不能遮住当前需要读的信息。

## 视觉系统

使用编辑式的暖白、深绿与橙色：

- 纸色 `#F3F2E9`
- 主文字 `#19362F`
- 次文字 `#52635C`
- 强调色 `#E79B40`
- 浅绿 `#C0D6BA`
- 深背景 `#102C25`

只用这六个基础颜色；阴影由基础色的透明度构成。正常阅读态的文字色对比度至少 4.5:1；透明入场中不能把低对比画面计为可读时间。

中文使用固定文件的 Noto Sans CJK SC Regular，记录文件哈希，禁用系统随机字体回退。可以用子集加速，但必须覆盖全部字幕并记录子集过程。

画面采用可单独控制的 SVG 路径、形状与文字。产品 UI 根据真实字段重构并标明“非操作录屏”。禁止用整页截图缩放替代内部动画。若采用照片或外部栅格素材，应准备至少最终使用尺寸两倍的原始资产；本片纯矢量，无须为了满足清单而添加照片。

这支片没有需要真实光照的三维产品，采用二维空间层次，不把旋转纸片冒称为真实 3D。如果后续加入真 3D，另行制定几何、镜头、光照和材质验证，不套用二维验收结果。

## 动作设计

为主物体指定稳定身份和一套随帧变化的几何数据。每次转场写清楚起点、终点、轮廓对应点和附属内容如何跟随。不能用整屏遮罩盖住换场，也不能用两张完整页面交叉淡化冒充形变。

轮廓使用固定点数和固定顺序插值，星形到圆角矩形在任意中间帧都有合法形状。矩形的中心、宽高、旋转及页层位置使用统一轨迹；跨场时复用同一组坐标，检查边界前后连续性。

为主要动作安排短预备、加速、减速、轻微超调和收敛。小幅挤压与拉伸要改变体量感，不能让文字跟着无限变形。光标走有目的的弧线，点击要产生可见选择和后续展开。页面与标题的附属动作稍后跟随，不要所有东西同时开动、同时停止。

让运动有不同密度：开场快速建立标记，中段展开和收束，最后降低运动幅度供阅读。主体需要持续、有意义的变化；不能用边角计时器、随机飘动或无关粒子掩盖静止。

不使用装饰性的闪白、故障、粒子雨或重复全屏扫屏。镜头只在揭示对象关系时推进或后退。快速动作使用真实多时间样本的运动模糊；不能把一层永久模糊称作运动模糊。

最终检查最长静止段不超过 0.5 秒、每 30 秒累计静止不超过 1 秒的目标。20 秒片按比例使用约 0.667 秒的累计目标，同时分别报告全画面与去掉页眉页脚后的主体区域结果。像素变化不等于动效有意义，必须结合观看判断。

## 声音和时间轴

先完成声音结构与统一时间轴，再做正式动画样片。配乐原创程序生成，120 BPM，20 秒，48 kHz stereo；保留无动作音的纯音乐版本。无对白，不能声称完成了语音自然度、口型或旁白评估。

把场景边界、节拍位置、主要动作到达帧、波形收回区间、文件展开区间及运动模糊参数集中到 `timing-v2.json`。音乐与动画读取同一数据。重要声音锚点与视觉到达帧目标误差不超过 1 帧；代码锚点对齐和人感知的运动峰值分开验收。

短音效服务于收拢、点击、展开和归档，不要每帧加音。音效可以在动作瞬间被听见，音乐保持底层；总混音不得削波。原来源中有关音效相对音乐的冲突，以本任务这一明确混音选择为准并记录。

对最终 MP4 解码测量，目标 −14 LUFS，真峰值不高于 −1 dBTP。使用两遍响度处理后仍要复测最终编码文件。数字合格不等于悦耳，必须把是否经过人耳检查单列。

## 实现和阶段检查

实现应是可重复的逐帧函数：同一帧号、相同字体与数据产生同一画面。不依赖墙上时间、不受浏览器定时漂移影响、不用没有种子的随机数。固定依赖版本、字体和事实输入。

采用 SVG/resvg 生成画面，普通动作三个时间样本、高速转场七个时间样本，合成半帧快门运动模糊，FFmpeg 编码。Remotion 不是本任务必需条件，最终验收看画面和证据。

先渲染前 4 秒样片，实际检查字体、编号、星形与卡片连续变形、音视频时长与编码。再渲染 8.5–13 秒桥接片，检查原理图回到 README 的语义是否清楚。样片发现的问题先修，再渲染全片。

需要新的独立评审者审查分镜、各镜头及最终成片。评审者先不看实现代码，先看无声抽帧复述信息，再看需求并指出具体秒数的问题。每 0.2 秒抽帧，运动交界处加密；不能只看八个漂亮关键帧。独立模型评审仍然是模型判断，不代表真实观众评价。

任何一轮发现重大事实、遮挡、断裂或误读，都要修正后重新输出，复核改动区间，并记录前后差异。若某项只做了坐标测试而未完成视觉评审，应标记部分完成。

## 最终验收表

至少逐项报告：

- 视频尺寸、帧数、帧率、时长、编码、像素格式和文件 SHA-256。
- 最终混音响度、真峰值；纯音乐是否独立交付。
- 字体来源、基础配色、稳定阅读态的对比度。
- 首帧完整、标题和网址的可读区间。
- 八个构图区间是否符合计划。
- 星形→档案、行→工作台、图→README、文件→档案的几何与感知连续性。
- 主动作、次级动作、预备、超调、弧线、随动、运动模糊实际出现在哪里。
- 全画面与主体区域静止检测，原始事件及阈值，任何超标段。
- 每条实际名称、状态、技术描述与文件结构的事实来源。
- 分镜、样片、逐镜与整片评审是否完成，哪些意见已修复。
- 和参考作品仍有哪些明显距离；不能用技术参数替代专业质量判断。
- 未覆盖的能力：真 3D、角色表演、对白、竖屏和外部模型实测。

通过、未通过、部分完成、不适用必须明确区分。不要宣称这一次演示测出了模型能力的普遍上限，也不要将两次不同制作投入的结果叫作严格提示词 A/B 实验。
