# 共同任务与成片要求（两组逐字相同）

为“GitHub 项目研究集”制作一支面向开发者的真实产品片。讲清：收藏工具之后，在研究集中理解原理、查看来源，并用可验证的小实验继续研究。聚焦其中的 Kokoro 条目；任何波形必须标为教学示意，不能冒称实际运行模型。
片长恰好 20 秒，1280×720，16:9，60 fps。最后清楚显示“GitHub 项目研究集”和 github.com/yydshly/1020_codex_project。交付可播放 MP4 和完整制作源码、纯音乐版本、10—20 帧缩略图拼版、事实与质量检查证据、未完成事项及耗时记录。
产品真实资料、UI 源码、字体、原 favicon 和参考片在 shared/。使用真实 UI 重建可动组件，不得编造官方 logo。旧截图用于采样参考，其采集日期为 2026-10-20；事实以同包内本次冻结的文字资料为准。root README 中其他研究项目不是可读取的历史动效制作材料。
视觉要求：第一秒有清楚的内容钩子；主体和构图有变化；一个有意义的元素连续衔接全片，转场体现内容关系；动作流畅，速度有层次，快速动作有合理模糊；字可读、不重叠、不越安全边距，文字对比度至少 4.5:1；不要靠无意义的小动效掩盖停滞。第一帧完整，20 秒内冻结总计不超过 2/3 秒，任一静止段不超过 0.5 秒。颜色忠于实际产品，事实真实，静音也能看懂。
音频要求：原创音乐加合理事件音效，无配音；音效低于音乐（此项解决可能的音量指令冲突），约 −14 LUFS，真峰值 ≤ −1 dBTP；剪辑和关键声音与节拍相差不超过 1 帧。声音不能来自参考作品。
同包 reference.mp4 来自 Linear 官方 Introducing Linear Agent，仅用于私人研究品质标准，不能复制画面/音乐或作为本片素材；官网 https://linear.app/changelog/2026-03-24-introducing-linear-agent 。目标是与该参考摆在一起不显粗糙。网页将诚实展示达标或未达标结果。
不用征求确认，直接完成。工具固定为本机 Node.js、@napi-rs/canvas 或 @resvg/resvg-js、Python、FFmpeg/ffprobe 与读写/图像查看工具；不安装新包、不调用其他生成模型/外部 API、不上网找额外素材。生成全部动画代码，不准读取或复用既有 V1/V2/V3 代码、音频、影片、评审或另一组产物。

# 共同实验运行规则（两组逐字相同）

这是一场限时制作，预算优先于无限迭代要求。每组从调度开始最多 1,200 秒（20 分钟），包含读输入、思考、写代码、渲染、制作内评审和修改；提前完成可以结束。统一独立评审工具额度：最多 12 个全新 fork_turns=none 子代理，每次最多 1 个评审活动中；只能执行评审，不可把制作委派给额外代理。允许最多 2 个本地渲染 worker。两组串行制作；每组主代理与评审均继承父代理同一模型和推理配置，不得覆盖。模型配置继承可确认，供应端模型快照、采样种子及 token/费用不可测，不可声称已精确锁定。
这是相同时间与工具上限，不是相同 token 或金额。独立评审能力两组都可使用。所需的分镜、场景、成片评审应使用全新上下文代理；未完成的要求如实记录，不能以预算为由称已通过。不要向另一组或主协调员索取创意帮助。
所有输入仅限本 run 目录中的 input.md 与 shared/。只允许为模块解析访问项目 node_modules，不读旧版源码。所有写入限定本 run 目录；不要改网页或其他文件。引用 shared/ 资源时保留相对路径或明确来源。对任何需要主观听感而无法实际判断的项目写未验证。
最终候选必须保存为 output.mp4；只有预算内完成的最后完整候选计入比较。不要把失败探针叫最终成片。候选一旦完成可随时保存，再迭代；若截止时未交付候选，计为未完成，不给予额外补做时间。最后写 result.json，包含 status、start_utc、finished_utc、elapsed_seconds、output_file、review_agent_count、render_count、known_issues、unverified、unfinished_requirements；另写 ledger.md，保存每次独立评审及版本。不得伪造完成/评审/测量。
场景均为 20 秒产品片。相同预算不会保证完整执行所有长流程，未完成比例也是本次要观察的结果。你不知道另一个输入条件或评审结果，不要猜测对照结果。共同评分标准在 rubric.json。最终匿名评测在制作截止后由协调员统一执行，不反馈给制作代理。
