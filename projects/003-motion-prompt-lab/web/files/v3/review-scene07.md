## 问题（按严重性）

### P1 — f925 点击落在空白处，操作因果尚未成立（可修）

f922–926 的光标目标附近没有可见按钮、文字或路径节点；f925 仅能看见光标小幅缩放。第一项“理解原理”到 f927 才在光标左侧开始出现，随后第二、第三项依次淡入。因此静音解读是“点击空白后，标题式流程自动出现”，无法判断实际操作对象。与参考中“已有输入区域→提交→出现结果”的因果闭环相比，这里的点击像给动效加的打点。

建议先让真实可点击对象可见，再在 f925 点击，随后从对象展开路径；保留“研究中”，不要把路径画成已完成状态。若把首项出现当成 f925 的视觉结果，最早肉眼可辨帧为 f927，误差约 +2 帧，超过 ±1 帧；但 f925 的光标缩放本身与 timing.json 一致。必须区分“点击姿态对齐”和“结果显现对齐”，不能把二者都写成通过。

### P1 — f969–1010 存在 0.683 秒近静止段（可修）

ffmpeg `freezedetect=n=-60dB:d=0.5` 报告局部 1.150–1.833 秒（全局约 f969–1010）冻结 0.683 秒，超过单段 0.5 秒限值。RGB 逐帧差分没有完全相同的相邻帧（0 对），所以它不是字节级硬冻结；但该区间多帧全图平均差分仅约 0.002–0.03/255，抽帧看起来基本停住，少量压缩变化不能证明有可感知的呼吸。

建议给路径自身或承载路径的视图安排可感知、低幅度且有动机的连续变化，避免仅靠小图标/亚像素变化。重渲后用相同阈值复测，并看原速播放。该问题应记录为近静止检测失败，不应改写为“完全重复帧 0，因此通过”。

### P2 — f960–1032 的信息层级和高潮强度偏弱（可修）

三个主要词横向分布约 x100–1025、y320–367，下划线到 x1120，正文只占画面中部约 80 像素高。左下 `GitHub 项目研究集` 约 280×35 像素，底部又重复一次约 157×19 像素；重复品牌文字分散注意力。timing.json 指定 f900 为高潮，但该镜头前约 0.4 秒主要是小图标飞行与空白，再变成横排词语，视觉强度未形成高潮。

参考的 10–13 秒由输入面板变为结果面板，主体始终有清楚的空间与工作对象。本镜头可读、克制，但更像流程说明页，不能据此判定“放在参考旁边不会显得更弱”。建议删去一次重复名称，扩大或实体化路径载体，使点击引起明确的内容重组。无需复制参考的黑色、透视或版式。
