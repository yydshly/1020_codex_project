# 船、水下场景与 MiniMax 讲解修订

本轮针对“船像积木、看不懂调查、需要 MiniMax 语音、辨认不出水底”的实际反馈修改。与前轮字幕版验收分开记录。

## 可见变化

- 母船采用剖面曲面船壳、多层作业甲板、驾驶舱玻璃、舷窗、栏杆、救生设备、雷达桅杆、A 型吊架与绞车。首镜把黄色潜器从船尾下放到水中，之后跟随潜器抵近海床；不再在透明海面上直接俯看海床。
- 海面使用不透明波浪、水线接触泡沫和水上天空。镜头入水后逐渐转为蓝色吸收、远景雾化、悬浮颗粒与潜器灯光。深水关闭海面的底面，避免千米深处仍出现明亮水面横板。
- 两条航次均有七段通俗调查脚本。热液航次回答“没有阳光，喷口旁的生命靠什么生活”，沿出发、下潜、发现喷口、观察管虫、采水、取泥对照、返航推进。
- 新增调查步骤、水面/下潜/海床标识与镜头水深剖面。水深和纵向距离为压缩教学示意；不是实测海域或真实下潜时间。

## 真实语音资产

MiniMax `speech-2.8-hd / male-qn-qingse / speed 0.95`，14 个 MP3，共 4,553,112 字节、283.068 秒旁白。模型与接口见 [MiniMax 官方文档](https://platform.minimax.cn/docs/api-reference/speech-t2a-http)。每镜时长取 `max(原分镜时长, ceil((音频秒数+1)*10)/10)`，热液影片 148.5 秒，峡谷影片 149.3 秒。

`src/check-narration.mjs --decode` 检查所有音轨的完整解码、采样率/声道、时长、音量、文件哈希及旁白全文。14 段完整解码成功，非静音；ffprobe 容器时长与 API 清单一致。浏览器解码器剔除 MP3 padding 后可略短，因此片尾以实际媒体 duration 作为护栏。

密钥通过项目外环境文件读取，未进入网页、公共清单或日志。网页只播放已经生成的音轨，运行时不需要访问 MiniMax，也没有换用浏览器合成音色冒充 MiniMax。

## 播放同步与实际发现的修复

1. 初始本地 Python 静态服务给 MP3 的 `seekable` 为 `[0,0]`，直接设 `audio.currentTime` 会回到开头。改为先完整缓冲成对象 URL；实测 `seekable` 覆盖全段，影片 48 秒对应第三章音轨 6 秒，拖动后能准确继续。
2. 音频实际播放时间驱动影片，缓冲时镜头等待。较慢 WebGL 帧通过内部时钟校正追到媒体位置，不重新定位音轨。片尾保留短暂停留后进入下一章，不重复播放已经结束的音轨。
3. 暂停、继续、跳章、章内定位与倍速同步音轨。隐藏页面和退出导演停止旁白；关闭语音可继续字幕放映。
4. 补充受控异步测试：暂停后立即继续时，旧 `play()` 的延迟拒绝不得阻断新播放；静音后下载失败不得暂停字幕影片；切章后的旧资源不能覆盖新章；加载中定位要保留，销毁后回收对象 URL。

## 验收范围

桌面浏览器已实际验证 MiniMax 媒体播放、章内定位、跳章、2 倍速、暂停、退出停声，以及热液影片 0→148.5 秒、峡谷影片 0→149.3 秒自动播放至完成。完成后媒体暂停、完成提示显示，无自动循环。峡谷第5章实测影片95秒、该章音轨11.535秒，对应章起点83.5秒。

390×844 CSS视口内，最终导演页面的clientWidth与scrollWidth均为390；语音、字幕开关、章节、景别、播放和进度控件可操作。实际验证关闭语音后音轨暂停、字幕影片继续；重新开启后从当前章节位置继续，并恢复1倍速。此处为浏览器断点检查，不代表物理手机测试。最终截图：
