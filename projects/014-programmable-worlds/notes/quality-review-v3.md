## 当前结论

两件作品已从平面插画升级为真实三维，但所见最新截图仍不能认定与 Na Pali 同级别。当前主要差距是完整环境的自然连续性、不同尺度的表面细节、可信的水面与光照关系，以及近距离观察时的几何完成度。增加面数、叶片数量、反射分辨率或技术名称，本身不能作为画质通过的依据。

Na Pali 五张上游图是作者的离线渲染参考；它们不能替代本机完整实时源库的验收。待源库实际运行后，应从**同一后端、相同画布分辨率和相当观察尺度**获取本机参考，再进行两件作品的最终比较。

## 影响两件作品的共同上限

### 1. 当前实时核心并非 Cycles 场景的完整几何显示

[lookdev-v4-manifest.json](../../007-canal-blender-test/web/models/lookdev-v4-manifest.json) 记录导出时省略了 **686 个 BEVEL 修改器**。原始场景有 2,109 个对象，而当前 glTF 合并为 29 个 primitive，保留约 226,532 个三角面。合并有利于实时运行，但被省略的倒角使石岸、家具、木构等近景更容易出现生硬的直角边缘；烘焙图无法在移动视角下补回真实的轮廓和掠射高光。

**建议的最强复用路径：**在 014 自己的副本中，从 007 的 `.blend` 按相机可见范围导出 evaluated geometry，优先恢复关键轮廓的倒角、法线和接合。保留 007 原文件不变。不要将“再增加几组装饰”作为这个结构问题的替代。

### 2. 固定光照烘焙与动态氛围混合存在一致性上限

两件作品沿用 7 组固定时刻的烘焙表面，屋顶两组回退到 PBR；代码对 `MeshBasicMaterial` 设置 `receiveShadow = false`。窗景的晨光/黄昏/夜色主要改变曝光、环境与少数灯光，不能重新计算已烘焙在建筑表面的照明。因此应检查夜间建筑是否仍像白天亮着、室内外光向是否一致、动态物体接触处是否失去阴影。

质量优先时，可以先做**一个照明完全自洽的黄昏场景**，再增加经过分别校准的时段；不必保留三套只有曝光不同、互相矛盾的“昼夜”。若需要完整时段变化，应考虑独立的间接光烘焙与 PBR 材质/灯光，或为各时段重新生成对应照明资源。

### 3. 远景仍有“排树遮平面”的观感

最新两图都能看到桥后空旷平地和近似同高的疏树排布。源库的自然感来自连续地形、植被群落与大小尺度的组织，不是只靠细叶。故事的 `plantDistantBanks()` 仍用相近结构的 80 棵树铺在河道两侧；窗景用递归枝干和随机叶片。它们比粗球树更细，但单靠数量不能解决地形、树冠层级、岸边过渡和远处消失方向。

应先确定河道在视线内如何弯折和被真正地形遮挡，再组织近岸灌木、中层树冠与远丘。雾只负责空气深度，不能遮盖裸地、直线边界、几何接缝或突然消失的水面。

## 实际验收清单

下面以可观察证据做通过/未通过判断，不设置虚构的“电影感分数”或凭面数打分。

### A. 源库门槛（必须先完成）

- 全部原始场景功能保留，着色器与质量参数的保留检查通过；地形、侵蚀、植被、海水、天空和光照实际生成。
- 可见画面不是原图或视频贴片，连续帧确实变化；记录实际图形后端、分辨率和初始化阶段。
- 暂停使时间/水面等预期运动停住，继续恢复；0、35、75、128 秒等机位的实际视图明显不同。
- 驾驶控制改变相机位置/朝向，重置可回到原路线；不能只验证按钮文字变化。
- 全航线或等价覆盖检查中没有 GPU 进程崩溃、上下文丢失或长时间无帧；保留实际失败与成功记录。

### B. 统一视觉对照

- 源库和作品使用相同像素尺寸与清晰度设置，均从实际运行捕获；不拿缩小的作品图对比全尺寸来源，不靠原图/视频代替运行。
- 每件作品至少检查默认全景、关键近景和一个明显不同的机位。UI 隐去后的画面依然成立，文字不负责“解释掉”可见缺陷。
- 近中远的光向、明暗和空气深度一致；主要材质能通过轮廓、高光、粗糙度、细节尺度辨认。
- 没有暴露的有限场地边缘、平板远景、穿帮面、明显重复树行或大面积无细节表面。
- 水反射、岸线、物体接触和粗糙度随镜头连续变化；没有周期网格、冻结倒影、反射跳跃、色调重复映射或沾满全屏的“雨条”。
- 细节服务空间与情绪，不以过量噪声、雾、亮斑或叶片数量替代具体的表面、植被与构图问题。

### C. 可驱动与持续运行

- 测试在隐藏的项目专用运行器中进行；不激活桌面窗口、不发送系统键鼠，不影响用户正在使用的浏览器或其他应用。
- 用作品自身控制 API 驱动机位/移动/选择，并保存前后真实帧及状态；截图差异应与动作原因相符。
- 对窗景检查窗边→走近→河岸、天气、氛围、暂停与重置；对故事检查三机位、沿河航行、自由相机与两种信件结果。
- 记录实际分辨率、连续帧时间/停顿和 GPU 错误，不将后台标签页降频后的 1 FPS 或某一峰值当作稳定基准。驾驶若长时间没有画面响应，应判未通过。
- 先完成一套画质稳定且空间连续的默认体验，再扩展新时段、更多树、更多物体或开放范围。

## 推荐执行顺序

1. 完成源库后台完整运行与驾驶验收，保存可复现配置。
2. 固定默认黄昏机位与曝光，先修 shared canal 核心几何/材质和背景连续性；两件作品复用同一经过验收的核心资源，减少分叉误差。
3. 分别完善窗边近景材料、故事道具/机位，并进行实际多机位对照。
4. 再验收氛围、雨、水和故事状态变化；最后更新页面、引导图和结论。历史 2D 及中间三维截图保留为记录，不进入最终效果展示。

本记录是制作计划与现有证据判断；没有宣称源库已经跑通、两件作品已经达到来源级画质，或最终验收已经通过。

## 后续制作记录：真实共享资源

完成上述只读复核后，主任务提供了实际跑通的源库画面，包括 [35 秒本机实时画布](../assets/runtime-qa/2026-10-24T00-44-05-302Z/03-headland-35s-canvas.png)。现已直接查看该帧；它的多尺度地形、植被、光向、空气深度和水面结构，成为后续实际视觉对照的依据。前文“没有宣称跑通”仅描述最初复核时点。

014 新建了独立的 [导出脚本](../src/export_quality_scene.py) 与 `artifacts/quality-canal-evaluated.blend`，007 的原始文件保持不变。CPU 准备保留全部 686 个 BEVEL，评估 2,087 个可渲染对象，得到 501,844 个三角面。运行版再排除原有远处材质组、旧平地和旧长水面，由连续三维河谷补全环境；完整评估几何仍保留在编辑副本。

新材质把原始程序材质转换为独立的底色、粗糙度、切线法线和局部清漆贴图；原始对象坐标与世界坐标纹理关系被保留。十五组近景材质采用 2048–3072 UV 贴图，间接漫反射以 64 样本独立烘焙，仅对间接光做底色引导的 OIDN 降噪。底色不含光照，直接灯光、镜面反射与阴影仍由实时渲染器处理。

间接光以真正的线性 RGBE HDR 提供，配合 HalfFloat DataTexture，避免浏览器读取 PNG16 时把暗部间接光压成少量 8 位阶梯。PNG16 仅作为线性诊断副本保留。主屋顶 UV 覆盖率为 90.6%，中位三角面覆盖约 218 个纹素；这修正了旧屋顶 UV 过碎的问题，但不能替代完整场景的近景、运动与多机位验收。

资源路径和哈希见 `web/shared-scene/manifest.json`、`provenance.json`。`stage: "baked"` 仅表示资源烘焙/封装完成，不表示两件作品已经通过本文件的视觉与可驱动验收；最终仍须保存实际运行帧和操作前后的状态。

最终资源已封装并通过检查：GLB 43,749,240 字节，25 个 mesh、407,537 个三角面，47 个 glTF 物理材质图片依赖；十五组 HDR 间接光另行挂载。原始程序 World 以 4096×2048、16 样本重新生成环境 HDR。烘焙主文件的哈希在 glTF 封装前后相同，通道打包图片独立输出；几何属性均为有限数，法线长度最大误差约 1.2e-7，007 原文件哈希未变。所有后台 Blender 作业已退出。完整作品的实景截图、机位、持续运动和控制验收由主任务随后执行。
