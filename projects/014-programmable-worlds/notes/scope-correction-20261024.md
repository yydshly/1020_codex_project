# 交付范围纠正 · 2026-10-24

用户指出两个入口实际上使用同一套场景。核查确认这一点成立：当前 R5 只制作了一套运河老街，窗边观察和雨巷来信是这套空间的两个交互原型。此前将一套场景的两种模式扩大为“两个独立作品已完成”，是交付范围错误。

原页面虽提到“共享运河空间”，同时仍使用“两件作品已独立重制”和“已完成”的交付表述。共享字样不能抵消这种范围夸大，也不能用运行检查次数、帧率或画质评审来解释成两个独立作品。

## 已实际完成的内容

- 原作 `napali` 已完整实时运行、在页内展示并可驾驶。这是作者原作的展示，不计作我们制作的第二个独立作品。
- 一套 R5 运河老街，包含同一组建筑、室内、植被、水体、材质和光照。
- 模式 A：窗边观察、机位切换、移动及暂停水流。
- 模式 B：在同一套空间中增加 25 秒相机旅程、信件阅读与漂流选择。

两入口都加载 `web/canal-real/index.html`，只改变 `experience=window/story`；`main.js` 的建筑、室内、远景、植被、水体与船信创建均不按这两个模式另建场景，R5 光照包也完全相同。模式差别主要在 UI、初始状态、相机路线和信件选择。

## 状态与记录的纠正

首页和 README 已将当前两个入口标为共享场景的模式 A/B，项目状态恢复为“研究中”。交付记录改为 `scope-reopened`；修改前的 accepted 记录保存在 `delivery-acceptance.before-scope-correction.json`，没有覆盖原文件来伪造历史。

已有实际操作、视觉、数据和手机检查记录继续保留，它们说明现有这一套场景及其两种模式的已验证范围，不证明两个独立场景已经交付。原始报告与截图不改写。

## 第二个独立作品

用户已选“旧船坞与运河车站”，保留运河题材，另建空间布局、船坞/车站主体、地标与可操作事件。只有直接运行后能看到不同的空间内容、多个取景点成立，并完成对应事件和画质验收，才作为第二个独立作品交付。更换标题、机位、时间或颜色不满足这一条件。

引擎、基础材质、水体算法等底层实现可以复用；空间内容与作品体验必须能清楚区分。当前新作制作中，尚无可交付入口，页面不提供占位或虚假的运行链接。
