# AI 效果、技术控制与项目价值 · 2026-10-26

**原作是什么。** Na Pali 是 Leon Lin 的程序化海岸作品：代码生成地形、侵蚀、植被、海浪、天空与光照，再以航线和镜头组织观看体验。它体现的是针对特定风景持续调校的制作方法，不是输入任意图片便能自动得到世界的通用工具。本站保留来源与原作，完整实时控制通过本机运行桥提供。

**我们做了什么。** 我们参考这种思路，完成了老街窗景、独立船坞车站和漓江晨航三处实践，并积累航线、驾驶、画质选择、按需启动、暂停释放与实际对照检查等工程能力。当前价值主要是研究、可运行样例与工程经验；技术差异化、稳定省时和商业价值尚未验证，三个后续乘船方向仍是候选。

**下次怎样做。** 遵循“确认约束 → 固定模板 → 有界求解 → 独立验证”：先确认构图、尺度、观看位置和允许改变的部分；固定素材版本、随机种子与已验证模块，仅开放少量参数；在限定范围、次数和计算预算内比较候选；再以未参与调参的机位、连续路线、实际操作与性能条件验收。单图不能唯一恢复隐藏空间，评分也不能代替审美判断。已有部分参数和检查脚本，但这套流程的完整自动化尚未实现。

当前价值主要是研究思路、可运行样例和工程积累。技术差异化与商业价值尚未得到验证；我们也没有实现稳定的“输入一张图，自动得到高质量互动世界”的系统。本次仅归档讨论，M8 与验收范围不变。

## 三层能力需要分开看

| 层次 | 做什么 | 在本项目中的状态 |
| --- | --- | --- |
| LLM 辅助写代码 | 解释需求、编写场景与交互代码、定位问题、组织测试 | 已参与实现与返修；能写出代码不等于一次就能达到目标画质，仍依赖明确约束和实际检查 |
| 专用 3D 生成器 | 根据图像等输入生成资产或环境 | 可以作为后续生产环节，目前没有接入本项目；不能把其公开能力写成我们的实现 |
| 产品整合管线 | 将素材、布局、镜头、光照、交互、性能和验收连接起来 | 已有若干场景与配套工程，但没有把参考分析、生成、自动搜索和验收串成通用自动系统 |

Hunyuan3D-2.1 和 TRELLIS.2 主要面向图像到 3D 资产，可考虑用于单件船、建筑或道具；生成资产不等于完成一个可驾驶世界。[Hunyuan3D-2.1 官方仓库](https://github.com/Tencent-Hunyuan/Hunyuan3D-2.1)、[TRELLIS.2 官方仓库](https://github.com/microsoft/TRELLIS.2)

Marble 面向环境生成，官方展示从文字、图像、视频或粗 3D 布局生成、编辑和扩展世界。粗布局可作为空间控制参考；这些能力尚未接入本项目。[World Labs 官方介绍](https://www.worldlabs.ai/blog/marble-world-model)

生成器可作为生产环节，再补体验与工程要求；是否采用取决于效果和成本，不必预设竞争或替代。

## 如何让结果更可控

下表是后续可以采用的方法，**不是已完成的自动流程**。现有参数、固定机位与测试脚本只覆盖当前作品，尚未通用化。

| 控制方式 | 目的与边界 |
| --- | --- |
| 参考图分区、轮廓与深度约束 | 明确天空、水、岸线、山体和前景的关系；估计深度可辅助布局，但不是完整真实几何 |
| 固定场景模板、素材、随机 seed 和有限参数 | 把改动限制在可复现的范围，例如岸线宽度、山群间距、相机高度、雾与光照；仍要检查每个结果 |
| 有界自动对比与搜索 | 规定候选数、参数范围、目标与停止条件，比较构图、轮廓、遮挡或色调；不能只追一个分数而忽略其他机位和体验 |
| 多视角、连续移动与性能验收 | 同时检查背面、近景、穿插、碰撞、加载和长时间运行；一张漂亮截图不能证明互动场景合格 |

Depth Anything V2 提供单目深度估计，可作为深度约束的候选来源；默认相对深度不能直接当成准确米制尺寸。[官方仓库](https://github.com/DepthAnything/Depth-Anything-V2)

Mitsuba 的逆向渲染教程展示了在明确场景参数和目标函数下，通过渲染误差优化参数的方法。这支持“限定变量后自动比较”的技术思路，不证明任意参考图都能自动复原，也不是当前网页已经接入的能力。[官方梯度优化文档](https://mitsuba.readthedocs.io/en/stable/src/inverse_rendering/gradient_based_opt.html)

单张图没有给出背面、被遮挡区域和全部尺度信息，不足以唯一恢复一个真实世界。生成器补全或工程重建只能给出一种合理解释。增加素材并不会自动保证画质：布局、比例、光照、镜头、材质协调和运行预算仍需共同处理。

## 已有积累与未证明的价值

已有代码和证据可以复用：场景生成方法、镜头和航线、参数控制、显式启动、暂停与释放、驾驶控件、画质档位，以及固定机位对照和实际检查经验。它们能减少再次处理相同问题的工作，但属于常见工程能力，不能据此宣称技术护城河。

尚未证明相较成熟工具能否稳定省时、改善画质或参与体验，以及是否有人愿意使用或付费。后期三个乘船方向仍是候选，商业价值不能由技术演示或静态参考图推出。

项目保持收口。只有出现明确用途，并有可衡量的省时、质量或体验增量时，再选择一个有限范围投入；没有这种增量，就保留样例与文档。

| 参数与版本 | 固定机位、seed、几何参数、素材版本和生成清单 | [M8 引擎清单](../web/lijiang-m8/engine.manifest.json)及代码中有项目参数；尚无统一的跨场景参数包 |

| 对照与验收脚本 | 固定相机、操作路径、性能条件、预期结果与报告 | [M8 检查脚本](../src/runtime-shell/lijiang-quality-m8-qa.cjs)和[验收记录](lijiang-m8-acceptance.json)已存在；不是通用审美评分器或自动优化器 |
