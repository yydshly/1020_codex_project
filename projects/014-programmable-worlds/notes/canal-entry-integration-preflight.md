# 新运河作品入口集成预备

记录时间：2026-10-24。本文是上线前的集成准备，不表示作品画质已经通过，也没有改变现用入口。

## 当前状态

原作入口为 `web/runtime/source-live.html`，通过后台原作 GL 实时引擎和本地 WebRTC 显示实际计算画面。原作源码、来源链接与作者参考图继续保留。新运河的实际页面为 `web/canal-real/index.html`；`experience=window` 与 `experience=story` 使用同一真实空间。R4 与四探针目前是候选参数，不是正式默认。

R5 使用单份独立光照配置和配套 GI 包。候选页面只有在配置资产校验、光照指纹和实际图像均通过后才能转成默认。不能将 R5 天空、太阳或反射环境与 R4 阴天 GI 混用。

R5 配置与 26 组完整 GI 候选现已发布，前端接入仅由 `giSet=r5` 启用；主页面入口未切换。最终光照指纹为 `80836c3f6f8529ef088136e9628e75e100a820760c3c27c148ade87356a01b34`。配置 canonical 精确字节、运行参数、GI 指纹及校准值必须一致；HDR 与模型另核 SHA/字节数。R5 复用已校验的 R4 同几何模型，不复制另一份模型。

从最终 RGBE 文件的太阳残差质心，按 pinned Three 的实际 `equirectUv`、取反 Euler 和 CubeUV 渲染目标分支反算，天空太阳方向为 `[-0.4636555024,0.7417550866,0.4845853552]`，与方向光夹角约 `0.00045662°`。这是 CPU 的坐标一致性验证，实际画面仍须 GPU 验收。

## 最终入口修改范围

- 主页面两处作品预览的 `data-src` 指向同一 `canal-real/index.html`，分别传 `embed=1&experience=window`、`embed=1&experience=story`。候选验证期间还需显式传已批准的 `giSet`、`probes=1&streetProbes=1`。
- 两张作品的预览按钮和文字入口一起更新，避免从新预览跳回旧模型。旧 `demos/`、历史记录和历史链接保留为历史资料。
- 窗景说明与真实功能对应：窗边第一人称观察、滚轮走近、WASD、河岸/店铺机位。不能继续描述新作品没有提供的雨量或冷暖切换。
- 故事说明与真实功能对应：25 秒旅程、暂停继续、同一物理信的拾起阅读和随船漂流、重新开始。
- 主页面仍保留原库链接、页内可驱动的原作、明确的来源和扩展方向。

## 场景切换与释放

沿用 `web/app.js` 的串行切换机制。任何时候只运行一个作品文档。滚动时保留已有的 160ms 防抖与可见面积迟滞，避免相邻预览交界处反复启动。

1. 先向当前作品发送不可见消息，暂停时间推进与输入。
2. 原作等待 `sourceLive.stop()` 完成，确认后台 GL 引擎已关闭；运河调用幂等 `canalReal.dispose()`，停止 RAF、UI、输入、局部探针和水面并释放 WebGL 上下文。
3. 等旧 iframe 实际抵达 `about:blank`。释放失败时停止下一作品，不同时留下两个 GPU 场景。
4. 读取最新的目标预览，再给唯一新 iframe 赋值。先前滚动选择已经过期时不启动那个旧选择。
5. 新 iframe 的载入事件发送当前可见状态。页面隐藏只暂停当前作品；普通焦点变化不销毁并重建。

现有 `app.js` 已实现上述核心顺序。新作品异步载入各阶段检查 `disposed`，旧文档不会在卸载后重新启动渲染。

## 回切与热启动的范围

原作后台服务和外层应用可以保留，但 `sourceLive.stop()` 会销毁该次原作 GL 窗。运河退出也释放全部 GPU 场景。因此回切会重新建立场景，不能宣称即时恢复或保留 GPU shader。原始扫描纹理仍可使用正常 HTTP 缓存；GI manifest、模型和压缩图继续使用 `cache:no-store`，保留完整校验，不删除任何缓存目录。

先以真实 `source → window → story → source → window` 往返记录首帧时间与场景释放完成时间。只有实际结果支持时才说明第二次载入更快。此阶段不为提速引入多场景常驻或大体积后台内存副本。

## 新入口的实际验收

旧版 `src/runtime-shell/hub-acceptance.cjs` 只识别旧的 `napaliControl/worldAcceptance`，不能据其旧结果宣布新入口通过。新验收使用 `sourceLive` 与 `canalReal` 的实际状态：

- 原作：源引擎 ready、实际视频解码帧继续增长、驾驶改变真实相机；退出后 service `sessionActive=false`。
- 窗景：GI 与光照指纹匹配、局部反射 ready、真实窗景出帧；拖动观察不平移相机，移动受实际室内/河岸/窗墙/桥体约束。
- 故事：真实时间走完 25 秒，暂停期间不前进；拾信确实重挂接相同物体并展开，漂流仍留在同船；读信后可重播。
- 切换：任何时刻非空作品文档与活跃原作 GL 会话不重叠；原 iframe 实际卸载后新作品才进入运行。快速连续滚动、载入中离开和再次返回也纳入。
- 画面：窗口、河岸、店铺、故事终点都保存实际 canvas 和完整 HUD。隐藏窗口的 `capturePage` 可能滞后于 canvas，先等多帧，再检查两种证据。
- 尺寸：实际 640×520 内嵌预览和 390×844 窄屏，纸张完整留在 HUD 可用区域，正文估计至少 18 CSS px，无横向溢出。

运行测试通过与源作同级画质是两项独立判断。正式入口只在实际图像质量也被接受后切换。

上述 hub 脚本现已更新到新 API，仍未执行。`NAPALI_HUB_CANAL_GI=r5` 只在隐藏测试文档中设置候选预览地址，结果写独立的 `hub-canal-candidate-acceptance.*`，不会据此宣称正式入口已经切换。验收包含 `source → window → story → source → window` 往返耗时、真实 canvas pointer 事件、按住约 450ms 的 DOM KeyW、源作自有隐藏 webContents 的极大拖动归一化，以及上一场景卸载和 GL 会话关闭。

`NAPALI_QA_OFFSCREEN=1` 可让本任务隐藏 QA 客户端使用 OSR，目标 30fps；默认窗口行为不变，始终 `show:false/focusable:false`。实际每段单调时刻、完成帧和 paint 回调被写入证据，完整 QA 还独立观察四秒帧率。工作耗时 `lastFrameMs` 不解释为 FPS。`NAPALI_CANAL_QUAY_AB=1` 在同会话附加下述两个候选机位的实时捕获。
