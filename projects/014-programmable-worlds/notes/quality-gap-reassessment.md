## 差距来自哪里

| 层面 | 源作实际机制与画面 | 当前作品的差距 |
| --- | --- | --- |
| 大形与细节层次 | 侵蚀地形、陡壁沟壑、岩层、树冠、岸线相互关联；轮廓从大尺度到微小尺度都不规则 | 主体是三栋重复立面；门窗、书和道具以规则简单形体为主。增加纹理不会改变这些轮廓和体积关系 |
| 地表与植被 | 地形属性参与植被分布，坡度、排水、暴露度改变岩石和森林；近景有实际遮挡层次 | 新林地反复实例化少量叶云与树干结构，虽然顶点很多，形态语言仍重复。平坦地面上的噪声与零散草丛不能形成同样丰富的地貌 |
| 水体 | FFT 波谱输出波高、横向位移和坡度；浅滩破浪、海床深度、岸线暴露度、泡沫及水色互相影响 | 当前主体仍是一张平面反射图，用几层噪声法线改变采样方向。它能动、能反射，但没有源作那套有空间结构的水体系统 |
| 天空与空气 | 体积积云具有光学厚度、朝阳方向的自遮挡、云边层次；薄云和距离雾共同组织空间 | 当前以固定 HDR 天空、均匀指数雾和场景光照组合，缺少源作天空与空气中的体积变化 |
| 材质与照明 | 地貌形状、材质属性、遮挡和光照在同一套着色逻辑里配合，反复针对参考照片调整 | 街区静态漫反射烘焙、新道具实时灯光、天空环境和水反射分别拼接。局部缺陷修好了，但大面积材质与光照仍缺少照片中的复杂变化 |
| 构图与制作方法 | 镜头、地貌、海浪和光向一起塑造每个景别；固定版本 README 明确记录按海岸照片逐轮比较 | 当前主要以“能够驾驶、没有破面和界面错误”为迭代门槛，未持续以源作画面作为画质门槛 |

根本的实现方向错误是：在展示 napali 后，把两个扩展作品转向了另一套旧运河模型与 Three.js 场景，而没有继承原作已经成立的地形、水、植被、天空和光照系统。Three.js 本身不是画质低的原因；问题是现有场景和渲染实现没有覆盖源作提供的视觉信息层次。4K 贴图、更多三角形、更多烘焙贴图和更精确的显示变换，都不能自动补回这些缺失。

## 应当采用的后续方向

1. 先在我们的页面中直接显示完整原作的实时输出，并让页面控件实际驱动同一个原作渲染器。启动命令、折叠参考图或外部应用入口，都不能代替页面内可见的原作体验。
2. 用户已选择保留运河题材，重新制作写实场景、植被、水体与完整光照。先制作一段有限街区，逐项检验建筑比例、石岸结构、深窗、扫描材质尺度、自然植被和统一照明；不继续用增加贴图和三角形数量代替场景重做。
3. 窗边停留与雨巷来信继续共享这一条重做的运河。先确认实际运行的基准镜头达到目标，再铺开机位、移动范围和故事互动；旧原型保留作交互研究，不能作为新作完成结果。
4. 每轮同时保留源作与新作同尺寸、相近景别的实拍对照。功能通过、没有硬错误、画质达到参考，分别记录，不能互相替代。
