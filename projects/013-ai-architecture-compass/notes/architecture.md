# 本静态手册的实现结构

本项目目标是呈现讨论与方法，不运行真实业务后端。

1. `src/catalog.json` 是方法、流程、组合与约束的内容来源；构建时同时用于静态正文与完整 SVG。
2. `src/build.py` 负责组装网页和来源，`src/build_guide.py` 负责向量图布局，避免手工维护两份方法正文。
3. `web/decision-model.js` 以纯函数维护推荐规则、任务卡填写状态与 Markdown 生成，浏览器与 Node 回归检查共用它。`web/app.js` 维护页面事件、筛选、最多三项对比、任务表单、教学切换和文件导出；用户输入只通过文本节点、文本框值或下载文本输出。
4. 不读取真实项目文件，不发送用户数据，不接入模型或其他远程运行服务。
5. `web/` 只包含静态公开产物和模板；发布由研究集既有流水线处理。

这是适合本次范围的简单结构。复杂业务、可靠事件交付和微服务是手册的教学内容，不是网页已实现的功能。

引导图由 `build_guide.py` 输出一张完整 SVG 及章节、架构卡的原图坐标。`build_viewer.py` 使用相同 catalog 生成文字视图，以章节元数据生成导航。`guide.js` 在同一张原图上裁切当前章，整图模式恢复完整范围；图像缩放用统一比例换算阅读位置。文字模式直接展示 HTML，适配窄屏和辅助阅读，无需加载外部资源。

## 本轮维护的实际约束

- 单一外部接入、后台任务、数据重要性不会自动触发模块化；明确标注多个独立业务能力后才给模块化候选。
- 微服务、CQRS、事件溯源保持条件性评估，组合多个压力也不能把它们升级为必选。
- 任务卡的填写计数不产生“通过”状态；实际执行证据始终留给真实实施后记录。
- 12种方法的新增字段同时渲染到详情、并排对比或完整图，主要正文继续使用同一内容源。
- 不把输入写入浏览器存储；页面明确提示刷新后不保留，并提供预览、复制与下载。

上述推荐和任务状态有 Node 内置回归测试。浏览器检查负责确认 DOM 展示、选择限制、复制下载与响应式布局。
