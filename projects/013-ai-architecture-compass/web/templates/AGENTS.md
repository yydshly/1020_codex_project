# AI 工作约束示例

使用说明：将适用内容合并到目标项目已有指令中，保留既有数据保护及业务规则。
下列资料路径、模块名和命令需要按真实项目填写。本模板尚未配置任何检查。

## 开始任务

- 读取实际适用的指令文件，按改动范围读取架构说明、模块规则和相关 ADR。
- 先定位本次用例、规则 ID、责任模块与公开入口，以及公共接口和数据模型是否变化。
- 为关键规则确认一个会破坏它的反例及相应检查；缺少检查时如实标明，不把计划当作已有保障。
- 普通局部任务简要说明；跨模块或重要数据变化说明影响与验证办法。

## 实现边界

- 按架构说明中的公开入口与依赖方向实现。
- 核心业务通过约定接口使用外部技术；厂商数据在接入处转换。
- 共同业务规则归明确的责任模块统一维护，避免多个入口各自实现。
- 涉及版本保护时，用实际存储支持的原子条件更新或等价并发控制保障版本匹配与写入；验证同一版本的并发提交不能都成功。
- 保护重要数据与未保存内容。备份、迁移和恢复遵循项目已有规则。
- 不将当前任务顺带扩展为无关重构。

## 遇到结构压力

- 明确指出现有规则或边界无法承载需求的原因。
- 给出最小候选调整、影响、代价、兼容与失败恢复办法，用实际场景检验收益。
- 不为通过检查直接删除断言、隐藏失败或放宽边界。
- 已采用的调整同步到代码、接口、架构说明、ADR 与检查。

## 交付

- 执行项目实际存在的检查：在此填写命令，不编造已通过的结果。
- 核心规则用需求与失败场景验证，涉及存储或外部适配时补充集成验证。
- 按规则 ID 报告实际命令或场景、执行版本、结果与证据位置；区分通过、失败、未执行和未覆盖。
- 报告改动及遗留问题；静态导入检查不能代替业务行为和真实存储验证。
- 边界、公共契约或架构决策变化时，说明文档及检查是否同步。
