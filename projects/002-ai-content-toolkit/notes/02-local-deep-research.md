# Local Deep Research 如何把问题变成研究报告

它面向的是“我想理解一个问题”，例如“几种本地文件搜索方案各适合什么场景”。输出的价值在于整理证据与引用，帮助你继续核对和判断。

## 工作过程

程序将 LLM 与搜索来源连接起来：围绕问题搜索、读取结果、补充信息，最后综合成报告。官方支持多种研究策略，也可把下载的来源建立为自己的资料库，再用于之后的研究。

LLM 负责组织问题和生成解释，搜索后端负责找到资料。这两种能力分开配置，因此“安装了应用”并不代表模型和搜索已准备好。

## 环境和边界

可使用 Docker 或 Python Web 应用。研究版本的 `pyproject.toml` 要求 Python `>=3.12,<3.15`；README 的 pip 路径还要求准备 Ollama 或兼容的模型端点以及 SearXNG。

“Local”不等于所有配置都不联网：使用云端模型时会发生模型调用，搜索公开网页也需要网络。输出带引用有助于审查，但引用可能不支持旁边的全部结论，仍要读原文。

## 第一次实验

用一个边界明确的问题，例如“为本地资料库比较关键词检索与语义检索”，要求报告包含依据与局限。抽查五条具体结论：引用能否打开、是否真的支持结论、是否遗漏适用条件。记录总耗时、模型和搜索配置。

**理解检查**：报告写得流畅，与报告有充分证据，是不是同一回事？

## 值得学习的设计

可以把报告视为可复核的中间产物：研究完成后，先人工核实，再改成视频文稿或播客资料。这样能定位错误来自资料搜索、模型综合还是后续改写。

## 固定版本与来源

### 深入补充（2026-10-23）

沿用固定版本，核对的是代码结构与能力边界，未部署或复现基准。输入除了研究问题，还包括研究范围、模型端点、搜索来源、策略和深度设置。输出可包含综合文本、来源与引用、问题和动作记录；实际字段随策略与入口变化。

**系统分工**：语言模型提出查询、解释资料、选择动作和写报告；搜索后端返回候选来源；内容工具取回页面或资料；程序组织调用、上下文、来源与终止。它组合已有能力，不在主流程训练基础模型。资料库的索引与检索也不是修改模型权重。

**策略不相同**：`source_based_strategy.py` 按设定轮次生成问题和搜索。第一轮可包含原问题，后续轮次用累计结果作为上下文，最后筛选并综合。`langgraph_agent_strategy.py` 使用工具调用 Agent：模型产生工具名称与参数，程序执行，将结果放回上下文，再让模型选择下一步。工具可包括主要搜索、专门来源、内容读取和启用时的子主题研究；不能把一个模式的行为当成所有模式默认行为。

**阅读不等于全文已覆盖**：`fetch_content` 可禁用、返回提取文本，或由模型按关注点摘取内容。页面读取、上下文与摘要输入都有长度和可访问性限制；搜索结果可能只是摘要。不能因为来源出现在列表中，就声称已经通读并核验全文。

**何时结束**：Agent 可以不再提出工具调用而返回答案；程序也有递归步数边界、取消与异常处理。达到上限或工具不可用时，已有资料可能进入兜底综合。正常生成报告与知识充分是两回事，应结合过程状态与未解决问题解读。

**引用如何产生**：收集器记录来源证据与编号；标准引用处理器将编号、标题、URL 与内容提供给模型，并要求使用这些编号。可选的来源一致性检查仍是模型判断。能打开出处不表示支持结论；相同网页不同摘录也可能成为多条证据，编号数量不能直接当成独立来源数量。

**详细报告**：`IntegratedReportGenerator.generate_report` 根据初步发现组织目录，再为各小节继续研究和生成内容，最后拼合正文与来源。它可能增加搜索和模型调用，不是仅将初稿拉长；质量需按证据覆盖、适用条件、矛盾与未知评估。

**本地边界**：应用、模型推理、搜索和阅读是不同环节。可以使用本地模型，也可以把提示与材料送入云端模型。公开网页研究需要网络，自建 SearXNG 也可能把查询交给上游引擎。纯本地资料任务需要逐项配置，不能从项目名推出绝对离线或隐私保证。

**网页教学**：保留四步研究推演与两种引用结论的对照，原理页以两张可点击的策略流程图展开循环、分工和出口，另有详细报告路径与引用示意。方案甲、乙和材料 A、B 明确标注为虚构教学内容；没有真实搜索或模型推理。材料只说“支持编号检索”，不能因此推出“所有场景最快”。

**实验方案**：对同一个范围明确的问题，记录模型、日期、来源、策略与读取设置；分别观察问题生成、工具调用、读取和失败，抽查 5 条结论是否获得原文支持，再比较两种策略的耗时、调用量与返工。尚未执行。

### 讨论理解与实际代码的差异（2026-10-23）

我们的概括是“从整体到细节，搜索、理解、补查，多次循环后形成报告”。这抓住了模型与工具通过资料反馈协作的机制，但不能据此推断每次执行都先全面规划、每轮都更深入或最终查清全部事实。

- **按轮次收集来源**：模型生成一批问题，程序并行搜索、累积结果。后续提问使用累计结果中受 `search.question_context_limit` 限制的最近部分。`for iteration in range(1, iterations_to_run + 1)` 控制轮次；轮内记录是轻量搜索元数据，主要综合在轮次之后。第一轮是否搜索原问题受配置和长度条件影响；没有问题时可跳过该轮搜索。
- **Agent 选择行动**：模型在可用工具与当前上下文中选择动作，输出工具名与参数，程序执行并返回结果。模型可继续调用工具，也可直接输出答案；子主题研究需要启用对应工具。`recursion_limit` 限制执行，触及上限且已有来源时可能综合部分结果。提示词鼓励资料足够时回答，不等于有客观验证器确认研究充分。
- **上下文不是模型训练**：迭代更新当前任务中的资料、上下文和输出；并不修改模型权重。资料入库供之后检索也不是训练基础模型。
- **阅读和核验有边界**：搜索结果不必等于全文；提取正文、聚焦摘取及模型上下文都可能受限。可选事实检查仍是模型判断，引用需要核对支持关系。
- **详细报告更贴近“整体到细节”**：先有初步研究发现，再确定章节，按小节继续研究，最后格式化报告；不把这条报告路径当作所有策略的必经开头。

产品价值在于将模型、搜索、读取、来源记录、上下文与终止条件组织成可运行、可追溯的过程。用户规定目标与角度；程序能落实可用工具、轮次或步数等边界；模型承担语义分析和生成。提示词中的要求需要检查是否遵守。部署是运行准备，研究质量仍要看证据覆盖、反例和未解决问题。

网页原理页的两张图可以点击节点查看对应行为与代码入口；图中的循环线和出口是对主路径的教学简化，并非实际执行日志，也没有发起模型或工具调用。
